## Goal

Make **declaring** verification for ad-hoc measurement work cheaper than **not** declaring it, without making a declared goal easier to satisfy than the work deserves. The Axis-B gate already does everything a declared goal asks of it; in session 288 it never ran once, because `goal.json` was never created, and ten measuring instruments lied without a gate to contradict them — all ten in ad-hoc work, zero in PLAN-governed work. This PLAN (1) repairs three defects in the gate and its command prose that make an *empty* or *stale* goal indistinguishable from a good one, (2) ships a **rendering contract** — the properties an evidence file must have before a `judge` may read it, learned from sixteen errors across two sessions — and a renderer that refuses a goal which fails it, (3) ships **three** templates over instruments that exist or are built here, eliminating one the design proposed, (4) sites the trigger where the agent can actually receive it and fixes its kill criterion **before** any replay, and (5) rules what a goal does when the evidence it was pinned to moves out from under it.

## 1. The problem, as measured (LOCKED — reproduced from the s288 census and the s289 field test; the handoffs are gitignored, so this PLAN is the tracked home)

### 1.1 The mechanism exists and works

`.claude/hooks/_goal_gate.py` runs every `check` criterion at every Stop as argv without a shell, requires `timeout_s`, treats the exit code as the only truth, holds `judge` residue for the `goal-evaluator`'s refute-not-bless mandate, and reports through Telegram and the `evaluations[]` trail. Its control flow is a flat sequence of named ADR-0018 outcomes; the seventh (`contended`, PLAN-0120) is precedent for adding one. **Nothing needs building there.** With no `goal.json`, or a goal whose status is not `active`, `run_goal_gate` returns `None` and the Stop proceeds to the classifier unchanged — the gate self-quiesces silently, so *not declaring* costs nothing and is noticed by nobody.

### 1.3 What they have in common

- **Not one would have been caught by reading more carefully.** Every catch came from numbers contradicting each other — `139≠140`, `8≠2`, `had_model=True` against a prior reading, four arms OUT OF BAND, `PASS` beside `exit 1`.
- **A control must be exposed to the same failure the claim is** (#8) **and be about the same subject** (#14). A control that certifies a different property, or a different model, certifies nothing in doubt.
- **A report that prints only PASS/FAIL withholds the evidence it collected** (#12, #13, #15). Three of the six s289 errors were one-step diagnoses *only* because the instrument printed its values.
- **The exit code and the printed verdict can disagree** (#13). The gate reads the one; the human reads the other.
- **A `check` has an evidence basis, and the basis can move** (#11). Nothing in the gate, the command prose or the schema names this.
- **CLAUDE.md §8 already states the rules that would have prevented several** and they were skipped anyway. More prose is measured not to be the fix; a *moment* is.
- **#7 and #1 were caught by luck.** The s288 catch rate is not a process and must not be read as one.

### 1.4 Two defects in the gate's own surface (verified on disk — §2 G1, G2)

- **A goal with zero criteria passes at its first Stop.** `checks_all_pass = all(…)` over no checks is `True`; `_judges_all_pass` returns `True` when there are no judges; both true is step 3 of the dispatcher, which sets `status: "passed"`. The module docstring's step 3 says *"all judge criteria carry a PASS verdict (or none exist)"* — the both-empty corner was never named. Not yet witnessed by a run; AC-1 requires it.
- **The command prose the declaring agent reads states a budget 5× the real one.** `.claude/commands/goal.md` tells the agent *"the total deterministic budget at Stop is 600 s"*; `DEFAULT_CHECK_BUDGET_S` is **120**, with a comment recording that 600 was unreachable by 3.3× against the Stop hook's 180 s timeout. A template summing to 300 s of checks, written to the prose, would be `skipped` at every Stop — unresolved, never a pass, and never explained.

### 1.5 What the s289 field test adds to the design input

The COMPANION's four templates were designed against s288's ten. Run for real, the value showed up as **shape** — print the values, control the instrument on the same subject, one mutation per assertion, name the evidence basis — not as ceremony. §4.1 makes the shape a checked contract; §4.2 ships fewer templates on top of it.

## 4. Design

### 4.1 The rendering contract — what every template goal must satisfy (binding on the renderer; the gate enforces only R1)

Learned from §1.2, one clause per failure class. The **renderer** (`tools/goal_template.py`, §4.2) refuses a goal that violates any clause; the **gate** enforces R1 only, so a hand-written goal stays as free as ADR-0018 made it, minus the hollow case.

- **R1 — not hollow.** ≥ 1 `check` **and** ≥ 1 `judge` for a template goal. The gate's rule is narrower: zero checks **and** zero judges is `invalid`, never `passed` (§4.3). A checks-only hand-written goal still passes — that behaviour is pinned by an existing test (G17) and is not reopened.
- **R2 — the instrument writes its own evidence file, and the file prints values.** Every check redirects nothing: the instrument takes `--report-to .claude/state/goal-evidence/<gid>/<id>.txt` and writes `lines=N consumed=N matched=M control_hits=K` (or the instrument's own measured terms), never a bare verdict. The judge reads that file; an absent or bare-verdict file is INSUFFICIENT-EVIDENCE. (Errors #12, #13, #15; G3 — tails never reach the trail.)
- **R3 — a control on the same subject, exposed to the same failure.** Every template carries a `C0` control the instrument runs on itself: for T-COUNT an `--expect` that must be refused; for T-ABSENT a pattern that must be found (`control_hits ≥ 1`); for T-ORACLE the witnessed-RED line. The control names its subject (the file, the model tag, the module) and the judge refuses a control placed where a miss could not hide. (Errors #8, #14.) The control is expressed as an instrument mode whose **exit code and printed line are derived from one value** — never a shell `!` inversion, which by construction makes the printed verdict and the exit disagree. (Error #13; §4.6.)
- **R4 — the expectation is derived, not chosen.** The falsifier (`--expect`, the pattern, the `stable_key`) is written **before** the reading and recorded as a `FALSIFIER:` line in the judge's `desc` (OQ-1). The judge refutes a falsifier that could not fail on the artifact as it stands. (Error #9 stays *partial* — no contract clause can make a wrong premise right; it can only make the premise visible.)
- **R5 — the evidence basis is named, and HEAD-pinning is refused.** Each check declares its basis in `desc` as `BASIS: tree | artifact:<path> | HEAD:<rev>`. The renderer never emits a `git show <rev>:` check; the gate's handling of one that exists is SD-2. (Error #11.)
- **R6 — transport-safe.** No `$`, backtick or `$(` anywhere in a `cmd`; every check has `timeout_s`; the checks sum to ≤ 100 s (budget 120; G2); project Python is reached as `wsl bash -lc "cd ~/work/vero-lite && ./.venv/bin/python …"` with `~`, never `$HOME`. (Errors #2, #3, #4 — structural exclusions that hold **only** if the reading is re-derived under the gate; nothing runs mid-Bash-call.)
- **R7 — provenance stamped.** The evidence file's header carries the goal id, the HEAD sha at the time of writing and, for T-ORACLE, the battery's run_id and sha256 (OQ-7, OQ-9). The judge compares the file's HEAD to the goal's `declared_head` (§4.3) and reports a mismatch as a finding, not a pass.
- **R8 — one goal file, no silent replacement.** An `active` goal that has not passed is **appended to** (ids prefixed `T<n>-`), never overwritten; `--replace` archives the old goal to `.claude/state/goal-history/` with `replaced-unpassed` written into it; a `passed` goal is archived and replaced freely (OQ-2). Replacing a hard goal with an easy one to clear the gate is the second hollow-goal loophole, and it is closed by making the abandonment a record.

### 4.2 The template set — three, not four (drafter's proposal; SD-3)

| Template | Trigger | Instrument | Status | Errors it catches (§1.2) |
|---|---|---|---|---|
| **T-COUNT** | about to type `grep -c` / `wc -l` / hand-add buckets | `tools/tally.py` — `--expect` is the falsifier; C0 = a must-refuse control | **shipped** (s288) | #1, #12 |
| **T-ABSENT** | about to report `0` / "no hits" / "not running", or a value read through a **window** | `tools/absent.py` — prints `lines=N consumed=N matched=M control_hits=K`; `--proc` excludes its own pid and any cmdline containing `absent.py`; the control must be **outside** any window the ad-hoc read used | **built by Step 2** (~60 lines + a planted-defect test) | #8, #10, the scope half of #12 |
| **T-ORACLE** | a new or changed assertion an AC will cite | `tools/probe_battery/` run **before** the goal (a battery takes the gate lock and mutates the tree — it can never be a check) with `--report-to` (Step 2); C1 = `check_battery_definitions.py`, C2 = the report says `PROBE-BATTERY: PASS` and credits exactly `expect_claim`, C3 = the unmutated test is green; the judge greps `entry_module` for a second emission site that could satisfy the substring | driver flag built by Step 2 | #5, #6, the witness note |

**Why T-GUARD goes.** Its C1 (real tree not accused) and C2 (planted defect reddens) are exactly what `test_guards_hold_on_the_real_tree.py` and the mandatory paired test module already enforce in the full suite, for every `tools/check_*.py`, on every commit (G14). A goal that re-runs CI adds a Stop-time cost and no evidence. Its C3 — *the report prints what it measured* — is not guard-specific and becomes contract clause R2 for every template. Its `--lite` variant for scratch scripts is where error #9 lived, and the COMPANION itself grades that *partial: cannot make `want` right*; the honest home for a scratch checking script is T-COUNT or T-ABSENT with R4's derived expectation. What is lost by eliminating it: nothing on #7 (CI has it), the *partial* on #9.

**Why T-ABSENT stays despite its unbuilt instrument.** Absence is the claim class CLAUDE.md §8 singles out — *"a zero or absence needs a positive control that finds a known one"* — and three of the sixteen errors are absence or window readings. The `grep -L` alternative (OQ-4) rests on exit semantics the COMPANION marks version-dependent and unverified; a 60-line instrument with a planted-defect test is cheaper than verifying `grep` across the two binaries a check can reach. **Note the coverage gap the COMPANION itself records and this PLAN inherits:** `tally.py` and `absent.py` are instruments, not `tools/check_*.py` guards — the real-tree test does not cover them by name pattern, so each needs its own module (AC-4, AC-5).

**Why not contract-only.** A contract raises the cost of declaring; only a renderer lowers it. The trigger problem is a cost problem — one command, ≤ 4 parameters the agent already holds at the trigger moment, `--dry-run` and `list` — and a contract alone would move the zero-cost path further from the honest one.

### 4.3 The gate repairs (Step 1 — strong oracle; bold by design)

1. **Zero criteria → `invalid`, never `passed` (OQ-5).** In `run_goal_gate`, after the battery stand-down and before `_run_checks`: a goal with no checks and no judges records a `_goal_gate:invalid_goal` trail entry (deduped by fingerprint, the warn-entry mechanism), pings once, and returns `None` with `status` unchanged under `enforce: false`; under `enforce: true` it parks at `blocked-pending-human` at once — a hollow enforce goal is a configuration error only a human can fix, and V2-D4 says evidence-missing is never a silent pass. The fix lives in the gate, not `Goal.from_json` (G17). Classification: the code did what its docstring said; the docstring omitted the both-empty case — `was an error` in the spec, not the code.
2. **`declared_head` on `Goal`.** A first-class field (the `enforce` precedent — an unknown field would be stripped on rewrite, G12), written by the renderer and by `/goal`, tolerated when absent. It is what R7 and SD-2 read.
3. **The budget prose pinned to the constant (OQ-8).** `goal.md` is corrected to 120 s and gains one paragraph each on R2 (write evidence to a file — stdout never reaches the judge), R5 (name the basis; HEAD-pinning is pre-merge only) and R8; a test parses the number the prose states and asserts it equals `DEFAULT_CHECK_BUDGET_S` — the cross-file pin the gate already uses for `CONTENDED_EXIT` and the Stop timeout — so the prose cannot drift again.

### 4.4 Goal lifecycle when the evidence basis moves (SD-2 — the s289 finding; Cray's)

The s289 goal failed `C1` at four consecutive Stops after its PR merged, and under `enforce: false` **the agent's context received none of them** (G5): each was a Telegram ping and a trail entry. Under `enforce: true` it would have received one block naming `C1=fail`, then a park. Either channel teaches the wrong lesson — that a gate which reliably fails after success is noise. Three dispositions, priced in SD-2. Common to all three: the renderer never emits a HEAD-pinned check (R5), `goal.md` says so, and `declared_head` is recorded. What differs is what the gate does with a hand-written HEAD-pinned check once HEAD has moved. The drafter's recommendation is the declarative eighth state: a check whose `cmd` matches `git show <rev>:` **and** whose goal's `declared_head` differs from the current HEAD reads `basis-moved` rather than `fail` — treated exactly like `contended`: no ladder, no defect in the trail, one ping naming the moved basis, and the goal stays `active` so the agent can clear or re-declare. Detection is **declarative, never inferential** — a tree-basis check that fails after a commit is a real failure and stays one — so this cannot mask a regression.

### 4.5 The trigger — where the nudge sits, and its kill criterion (SD-1; numbers fixed here, before any replay)

**The Stop-hook siting is not adopted.** Three of the COMPANION's four points are verified: a Stop `block` increments the chain and skips the classifier (G6); Stop fires after the reading was believed and, in s288, reported; and "wrote to `tools/` or `tests/`" reaches at most #5/#6/#7 — six of the ten never wrote a file. The fourth (a Stop `systemMessage` never reaches the agent, G19) is a harness property the drafter cannot verify from the repo, and does not need to: the repo has no `systemMessage` emitter at all (G7), so the only *existing* agent-reaching Stop channel is the costly one.

**Recommended siting (drafter-found refinement of the COMPANION's proposal): a third advisory in `_handle_bash` of `posttooluse_progress_observer.py`** — a sibling of `_shell_hygiene_warning` and `_venv_strip_warning`, joined into the same single JSON object the hook already emits (G8). No `settings.json` change; `test_settings_hook_wiring.py` is untouched; the test module mirrors `test_shell_hygiene_advisory.py`. Predicate: the command matches a **reading shape** — `grep -c`, `grep -L`, `wc -l`, `pgrep`, `sed -n … | grep`, `| head`, `| tail` — **and** `load_goal()` is `None` or not `active`. Emission: once per **session per shape**, keyed on `main_session_id(payload)` in the observer's existing counter state; the reason names the shape, states that no goal is active, and carries the renderer command **pre-filled from the observed command** (`--file`, `--field` or `--pattern` where the command told us). It never declares a goal — mention-as-intent is the classifier's recorded misfire family (G10).

⚠️ **Two honest corrections to the COMPANION's framing.** (i) *"Silent during PLAN work because a goal is active"* was not true in s288: no goal existed during PLAN work either. The advisory will fire in goal-less PLAN work, and that is correct behaviour — it is counted in the replay as a valid fire if the reading was quoted, a misfire if not, never excluded. (ii) The COMPANION's floor *"fires on ≥ 5 of the ten"* is unreachable by its own predicate: only **#1, #8 and #10** are Bash reading shapes; #3/#4 are the shell-hygiene advisory's; #2 is a wrapper's exit code; #5/#6/#7/#9 never went through Bash as a reading. A detector designed from those three commands will match them **in-sample** — that is the positive control, and it credits nothing.

**The kill criterion — fixed now (AC-9), the PLAN-0092 shape made prospective.** Replay corpus: the main-session transcripts of **s287, s288 and s289** (the transcript-parsing method PLAN-0122 §1.2 used for its 117-fire ledger), of which s287 and s289 are out of sample for a predicate written from s288. The report prints `corpus_calls=N raw_matches=M (p %) deduped_fires=F valid=V misfire=X reachable=k/3`. **Ship iff all three hold:** (1) `k == 3` — positive control, credits nothing; (2) **raw predicate match rate `p < 5 %`** of all Bash calls — measured *before* dedup, because once-per-session-per-shape would make any ceiling on deduped fires near-vacuous (three sessions × seven shapes bounds `F` at 21 regardless of how noisy the predicate is); the 30.8 % precedent (G9) is the same denominator and the same method; (3) **`X ≤ V`** on the deduped fires, hand-classified from the transcript with the class fixed here: a fire is *valid* iff the command's output was quoted as a number or an absence claim in the same or the next assistant turn, else a *misfire*. Failing any one is a finding: the advisory does not ship and the result goes to STATUS, never to a re-tuned predicate without a fresh pre-commit. If it ships, AC-11 re-measures the same three numbers after 14 days live; a breach demotes it to Telegram-only, the PLAN-0092 disposition.

**What the nudge cannot do, stated so nobody upgrades it:** it fires after the command, so #2/#3/#4 at the moment they happen remain the shell-hygiene advisory's; it cannot see a wrong premise (#9); and it cannot make the agent accept the paste. It buys a moment, not a behaviour.

### 4.6 Exit code and printed verdict must agree (the second new question — ruled, Code's)

Error #13 is a class: a verdict computed twice drifts once. Contract: every instrument this PLAN ships or touches (`tally.py`, `absent.py`, the renderer's control mode, the driver's `--report-to`) derives its final `VERDICT: <PASS|FAIL|REFUSED> exit=<n>` line and its exit status **from one variable**, and a unit test per instrument reads both from a subprocess and asserts they agree, with a probe that splits the two paths reddening it (AC-5). For the judge: the T-* judge text requires the evidence file's `VERDICT` line to agree with the trail's state for the same criterion id; a disagreement is FAIL, never averaged.

### 4.7 Discouraging a box-ticking goal — what is structural, what is not

Structural (offline-testable): R1 at the gate; R1–R8 at the renderer, which is the cheapest writer; R2's file-or-INSUFFICIENT rule at the judge; R8's recorded abandonment; the `render-handoff` line listing goals that ended a session unpassed or replaced (OQ-7). Not structural, and said plainly: the agent can still decline the paste, hand-write a hollow-but-not-empty goal, or write the evidence file by hand. The last is narrowed by R7's HEAD stamp and, for T-ORACLE, the driver-written report — narrowed, not closed (COMPANION §3.6 stands).
