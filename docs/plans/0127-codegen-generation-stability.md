## Goal

Make the seven-emitter pipeline (`services/engine/code_generator.py::generate_all`, `:917-940`) something a future vertical can rely on **without a further decision**: every ontology doc on disk — the six `verticals/<d>/ontology/<d>_v0.yaml` plus `ontology/core_v0.yaml` — emits all seven outputs **byte-identically across processes** (not merely twice in one process); the generated `schema.sql` **applies to Postgres** for every doc (today six of seven fail at their first statement, a pure table-order defect); the generated `orm.py` **matches the schema that applied**, per doc, in isolation (today two generated ORMs cannot coexist on the shared `Base`); the generated Pydantic constructs **real adapter records** through a real consumer seam for the served subset, with the unserved remainder registered in writing; the two committed generated modules stay byte-guarded; the lockstep guard and the CLI stop hard-coding one vertical; and the honesty ledger below is written into the record, including the plain sentence that **two of the seven outputs (TypeScript, context pack) cannot be proven correct without further Cray decisions**. Five PRs, one PLAN, no ADR.

## 0. Where this PLAN starts — the frontier

**Solved (do not re-do):** all seven emitters run for every doc and are byte-identical across processes (M1 / M1b, ⚠️ — the drafter could not re-run them, §1); the core ORM and core Pydantic committed outputs are byte-guarded (`tests/services/engine/test_shared_ontology_mechanism.py:134-141`, `:186-195` ✔); the qualified `core.X` cross-doc ref resolves to a bare table name (`code_generator.py:120-123` ✔) under a fixture test (`:57-65` ✔).

**Uncracked (this PLAN's work):**
1. **No test ever applies the generated DDL.** The SQL emitter writes tables in `object_types` insertion order (`code_generator.py:297-318` ✔) with inline `REFERENCES` (`:253-256` ✔), so a table that references a later table fails at `CREATE TABLE`. M2 (⚠️): 6/6 verticals fail at statement 1 (`UndefinedTableError` on fleet `depot`, energy `site`, aquaculture `farm`, building_materials `branch`, procurement `plant`, supply_chain `facility`); core applies (no refs); a fix-point retry resolves every vertical in 2 passes with 0 unresolved — ordering only. The only DDL test on `main` is DB-free by design (`tests/services/engine/test_sql_emitter.py:1-7` ✔). **PR-1 (Step 1, open) is the fix**; its measured readings are in Step 1 and §1 M2 (⚠️ Code s308).
2. **No test execs a generated ORM beside another.** Every generated ORM binds to the shared `services.db.base.Base` (`code_generator.py:645-646` ✔; `services/db/base.py:6` ✔). M3 (⚠️): fleet's generated `orm.py` alone → OK (10 tables); after `import services.db.models` → `InvalidRequestError: Table 'operational_event' is already defined`.
3. **Generated Pydantic is validated against real adapter rows for part of the served subset only** — energy and supply_chain tests (`tests/verticals/energy/test_energy_adapter.py:30-40`, `:68-74` ✔; `tests/verticals/supply_chain/test_supply_chain_adapter.py:31-34`, `:78` ✔), and one real runtime seam (G11). The fraction "~25 of 48 object types adapter-served; Alert / RecommendedAction / AlertEventLink (18 type-instances) never served" is ⚠️.
4. **Two of seven outputs have no correctness oracle:** TypeScript is never compiled (`code_generator.py:436` "light path — no tsc compile" ✔) and the context pack has a size budget only (`:701` ✔; `tests/services/engine/test_context_pack_emitter.py:121` ✔). Proving either correct needs a consumer, which is (B). This PLAN says so and stops.
5. **On `main` the doc set is not enumerated anywhere as a rule** (PR-1 ships the rule — `tests/support/ontology_docs.py`, G33). `test_cli_e2e.py` copies one vertical (`:26-41` ✔) and still expects **five** files (`:51`, `:57` ✔); the lockstep guard hard-codes fleet (`tools/check_ontology_orm_lockstep.py:70-71` ✔); the CLI has no `core` path (`services/engine/cli.py:28-33` ✔).

**Eliminated, not automated** (the dispatch permits this): (E1) a CI step that runs `vero-lite generate` directly — the pytest suites *are* the emitter runner and CI runs the full suite with Postgres (`.github/workflows/ci.yml:139-143` ✔); adding a second runner would be a second instrument to drift. (E2) the in-process "generate twice, compare" determinism check — vacuous for hash-seed-dependent ordering; AC-1 replaces it with a subprocess under a different `PYTHONHASHSEED`. (E3) sourcing generated-Pydantic instances for the never-adapter-served types from engine output — proposed eliminated under SD-6 (b), because no producer→consumer seam for those types exists and a fixture-fed check would agree with itself by construction (CLAUDE.md §8).
