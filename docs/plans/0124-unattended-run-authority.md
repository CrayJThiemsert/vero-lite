> **One-line frame.** Every gate in `.claude/hooks/` distinguishes **who** is acting (Code / Cowork / subagent). None distinguishes **whether a human is present**. This PLAN adds that second axis — *attendance* — as a fail-closed predicate that the git gate, a new host-state gate and (per SD-2) the subagent-spawn surface consult, so that a scheduled run carries **less** authority than a human-attended one instead of exactly the same.

---

## Goal

Make the hook layer attendance-aware: a run in which no human is present is detected **fail-closed** (absence or unreadability of the attendance evidence means *unattended*), and in that state the deterministic gates narrow what the agent may do with git, with MS-S1, and (per SD-2) with subagents — without duplicating anything the existing actor-aware gates already enforce, without touching the G1/G2 governance gates, and without altering the Stop-hook proceed arm that PLAN-0122 owns. The PLAN ships the predicate, the gates that consume it, the witnessed-RED evidence for each, and one live scenario in which a real scheduled routine is refused at the new boundary and the refusal prints the values it measured.

## 4. Design

### 4.1 Fail-closed forces an *attended* marker, not an *unattended* flag

The dispatch's requirement — *if the marker cannot be read, treat the run as unattended* — has a structural consequence: any design in which the launcher sets an "I am unattended" flag is **fail-open** by construction (a launcher that forgets the flag, a shell init that overrides it, a routine created in the UI without it, all read as attended). The marker must therefore assert **presence**, and everything else — absent, unreadable, malformed, expired, bound to another session — reads as **unattended**. The cost of that asymmetry lands on the right party: an attended human who forgot to mint sees a deny reason that tells them how, and fixes it in ten seconds; an unattended run that is wrongly trusted has nobody to see anything.

### 4.2 The predicate — one module, one test surface

`.claude/hooks/_attendance.py` (stdlib-only, like every hook) exposes:

```python
@dataclass(frozen=True)
class Attendance:
    attended: bool
    reason: str      # exactly one of the REASONS below
    session_id: str  # "" when the payload carried none

REASONS = (
    "token_valid",          # the only attended outcome
    "session_id_missing",   # payload carried no session_id
    "token_absent",
    "token_unreadable",     # OSError on open/read
    "token_malformed",      # not JSON / missing keys / wrong types
    "session_mismatch",     # token.session_id != payload.session_id
    "token_expired",        # now - refreshed_at > TTL (SD-4)
    "harness_override",     # a routine-only harness signal was present (§4.3, if Step 0 finds one)
)

def resolve(payload: dict[str, object], *, now: datetime | None = None) -> Attendance: ...
```

Every consumer calls `resolve(payload)` and embeds `attendance=<attended|unattended> reason=<reason>` in any deny it emits. The predicate reads **`payload["session_id"]`** — not `main_session_id()`, which deliberately returns `None` for subagents — because subagents share the parent's id (G6), and inheriting the parent's attendance is exactly the intended semantics: a subagent is never *more* attended than the session that spawned it.

**Token.** `.claude/state/attended/<sanitised session_id>.json`:

```json
{"session_id": "<id>", "minted_at": "<ISO-8601 UTC>", "refreshed_at": "<ISO-8601 UTC>", "minted_by": "userpromptsubmit:attend"}
```

`.claude/state/` is gitignored already (settings comment, `.claude/settings.json:3`). The sub-directory is **hook-guarded** (§4.5) so the blanket `Write(.claude/state/**)` allow (G9) cannot reach it.

### 4.3 The mint — anchored to the one event only a human keystroke raises

The harness offers exactly one event an agent cannot raise from inside its own turn: `UserPromptSubmit`. A new hook `userpromptsubmit_attend_mint.py` (registered beside the existing nudge, G7):

1. If the prompt matches `^\s*attend\b` (case-insensitive) → mint the token for `payload["session_id"]`, and return `additionalContext` = `attendance: minted session=<id> ttl_h=<N>` so the transcript records the measured value.
2. Else, if a **valid** token already exists for this session → update `refreshed_at` (presence decays; a human still typing is still present).
3. Else → do nothing, emit nothing.

Why the phrase, rather than "any prompt": a routine's instruction text is delivered to the session as its first prompt, and whether that delivery raises `UserPromptSubmit` is **unmeasured** (Step 0). Requiring the phrase makes the answer irrelevant to safety — a routine prompt refreshes nothing because there is no token for its fresh `session_id` to refresh (G17 is the residual: a routine that *resumes* a minted session; SD-4's TTL bounds it, Step 0 measures whether it can happen).

**Harness signal (Step 0-dependent, additive).** If Step 0 finds a `(field, value)` pair in the hook payload that is present **only** in routine runs (e.g. a `permission_mode` value, or a field the Desktop runner sets), it is recorded in `_attendance.py` as `HARNESS_UNATTENDED_OVERRIDE` and the predicate returns `harness_override` whenever it is present — **regardless of any token**. This is the unforgeable half of SD-3 option (b): the agent cannot edit its own hook payload (G8). If Step 0 finds a pair present only in *attended* runs, it becomes a second mint source in the mint hook — never a bypass of the predicate. If Step 0 finds neither, the token stands alone and SD-3 records that fact.

### 4.5 The host-state boundary — what follows from §8 plainly

CLAUDE.md §8 requires an **explicit Cray go before** warming or running a model on MS-S1, altering it over SSH, or changing host/global configuration outside the worktree. A typed go **cannot exist inside an unattended run** — there is no one to type it, and a go typed in an earlier attended session is not a go for this one (that is precisely the distinction the attendance axis draws). Therefore, in an unattended run, **no agent-initiated command may reach MS-S1 at all**, and the hook denies it deterministically rather than leaving it to a classifier criterion (G3). Two things are explicitly *not* swept up: the Stop hook's own in-process classifier POST (G4 — a standing, PLAN-0122-ratified transport, not an agent action; the only way to change it is PLAN-0122's business) and the `Notification` Telegram hook. If a future unattended workload genuinely needs a bounded MS-S1 call, the lawful shape is a **standing, PLAN-ratified allowance for a named command** — the same shape the classifier transport already has — and it is a Cray ruling, not a hook default.

### 4.6 What is ELIMINATED (proposed — entailed by any SD-1 ruling other than "full")

- The identity-matrix row **"Main Code scheduled (Phase 3.5) — allow"** (`pretooluse_git_deny.py:15-16`) is eliminated **as a category**. The matrix becomes four actor rows × two attendance states (8 rows, AC-9), and "scheduled" appears nowhere in it — scheduling is how a run *starts*, not what it *is*. PLAN-0010 minted that row for a loop that was then disabled because the row's authority was used to commit onto a live branch (G11); this PLAN discharges PLAN-0010's undischarged AC-4 in the process.
- The runbook sentence *"Permission mode: Auto (per ADR-013 D2 — composed identity gate handles the commit boundary regardless of permission mode)"* (`docs/runbooks/loop-dispatcher-scheduled-task.md:61-62`) is rewritten (Step 4): the claim is still true, but its implication — that a routine carries attended authority — is what this PLAN retires.

### 4.7 Threat model — stated so the marker is not oversold

The failure this PLAN defends against is **instruction-driven drift**: an agent that, with nobody watching, follows a fabricated `Stop hook feedback:` (L-5) or its own scope creep (G11) into an irreversible action. It is **not** a deliberately adversarial agent. A determined agent with full bash could forge the token in several deliberate steps (read its `session_id` from a hook's output, write the file by a path the guard does not spell). The guard raises that from "the injected line said commit, so I committed" to "I chose to defeat the guard", which is the bar the repo's other hooks meet (`pretooluse_git_deny.py:31-36` makes the same argument for `CLAUDE_TIER`). The only marker the agent **cannot** forge is one the harness sets in the payload (§4.3); SD-3 records whether Step 0 found one.

## Surfaced decisions — Cray's typed ruling required; every recommendation below is contingent on it

Reading order: **SD-3 → SD-1 → SD-2 → SD-4 → SD-6 → SD-5.**

- **SD-1 — What may an unattended run do with git?** Options: (a) **nothing** — every `commit|push|merge` denied; (b) **commit only** — local commits on a non-`main` branch, no push; (c) **commit + push branch + open PR, never merge** — the AC-5 table; (d) **full** — today's behaviour. **Recommendation: (c).** It is the posture Cray already runs by hand (CLAUDE.md §7: Cray merges; `--auto` is itself a merge and is denied here) — an unattended run's work becomes a reviewable diff with an explicit boundary, which is exactly what (a) and (b) throw away: (a) leaves the work in a dirty tree the next attended session must untangle, (b) leaves it on a laptop that sleeps when the lid closes (`loop-dispatcher-scheduled-task.md:109-112`). Against (c): a pushed branch is visible to the world on a public repo and a bad one costs a deletion; that cost is bounded by the PR being a draft. (d) is the state this PLAN exists to end. **Cray's because it sets what the repo's public history can receive without a human having seen it.**

- **SD-2 — May an unattended run spawn subagents (`Agent` tool)?** Options: (a) **deny** — simplest, one new hook, revived when a measured need appears; (b) **allow** — subagents already inherit attendance (G6) and are already commit-bounded and write-bounded by hooks that do not depend on attendance (G1, G8); (c) allow read-only kinds only (`explore-research`), deny writers. **Recommendation: (b).** The subagent an unattended run most needs is the `goal-evaluator` — the Axis-B verify loop (ADR-0018) is the mechanism that makes unattended work checkable, PLAN-0123 has just shipped the goal templates for it, and (a) would strip it from exactly the runs that need it most; (c) would also strip it, since the evaluator writes `goal.json`. Against (b): token spend and a runaway fan-out with nobody watching — the chain-cap and the loop-detect gate bound that today, attended or not. **Cray's because it is the autonomy fork ADR-013 delegated to PLANs, and because PLAN-0010 scoped subagents out of scheduled runs (`done/0010:131-133`) and this reverses that scoping.**

- **SD-3 — What is the marker?** Options: (a) **an env var set by the launcher** — simple; but a fail-closed marker must assert *attendance* (§4.1), and an attendance env var would come from the same shell init that sets `CLAUDE_TIER=code` (L-2), so it discriminates a Desktop-launched routine from a Desktop-launched attended session **only if Cray's attended launch path differs from the routine's** — asserted-not-verified (§Limitations R2); spoofable only in the weak sense (`pretooluse_git_deny.py:31-36`), but un-settable from the Desktop UI where routines are made; (b) **a harness-set payload signal the agent cannot forge** — strongest; existence unknown until Step 0 (`permission_mode` is the first candidate, G5; a routine-only field is the second); (c) **a human-minted, session-bound state token** under a hook-guarded path, minted only through `UserPromptSubmit` (§4.3) — always available, costs Cray one word per attended session, forgeable only by deliberate multi-step effort (§4.7). **Recommendation: (b) layered over (c) if Step 0 finds a routine-only signal — the harness override makes the token irrelevant for routines and the token covers whatever the harness does not; (c) alone if Step 0 finds none; never (a) alone.** Cray's because it fixes a **ritual he performs** every attended session (typing `attend`), and because only he can say whether his attended launch path differs from a routine's.

- **SD-4 — How does presence decay (the token TTL)?** Options: (a) **none** — session-bound only; the token dies with the session; (b) **4 h** from the last human prompt, refreshed by any prompt; (c) **8 h**. **Recommendation: (b).** A session Cray minted at 09:00 and walked away from at 10:00 is, by 14:00, unattended in every sense that matters, and (a) cannot see that; (b) is a working half-day and the refresh means an actively-typing Cray never trips it; (c) is a whole working day and was s76's shape (an hourly task running all day). Against (b): a long attended build in which Cray types nothing for four hours will see one deny and type one word. Also bounds G17 (a routine that resumes a minted session inherits at most the residual TTL). **Cray's because it is the definition of "present" the whole axis rests on.**

- **SD-5 — Should PLAN-0122's SD-4 decision log record `attendance` per fire?** Options: (a) **yes** — one additive field (`attendance=attended|unattended reason=<r>`) on the existing log line, no behaviour change; (b) no. **Recommendation: (a).** AC-12's next window would then split the proceed arm's defect rate by attendance — the number that actually decides whether unattended continuation is safe — at zero cost, and no window is open now (clock stopped s289/s290, `0122:309`), so the schema changes between windows, not inside one. Against: it is a write to PLAN-0122's instrument by another PLAN. **Cray's because PLAN-0122 SD-4 is his ruled instrument and a change to what it records is a change to what AC-12 can conclude.**

- **SD-6 — Is this PLAN the governance record, or does it need an ADR?** Options: (a) **PLAN as record** (§3) plus the two CLAUDE.md one-liners via Cowork; (b) a short ADR amending ADR-013 D2's identity matrix to add the attendance axis, this PLAN executing it. **Recommendation: (a).** ADR-013 delegated Phase 3.5's ratification to PLANs (`0013:333-336`), PLAN-0010 exercised that delegation for the very row this PLAN eliminates, and PLAN-0092/0122 used the same shape; an ADR would re-state hook code that is already the tracked, scanned surface. Against (a): "an unattended run has less authority than an attended one" is a durable principle, and principles live in ADRs. **Cray's because it is the precedence layer (CLAUDE.md §1) — the choice decides whether a future PLAN may widen unattended authority on its own or must amend an ADR to do it.**

## Limitations and residual risks — stated so nobody upgrades the guarantees

- **R1 — Forgeability.** The token is a drift guard, not an adversary guard (§4.7). The unforgeable option depends on Step 0.
- **R2 — Attended launch path (asserted-not-verified).** Whether Cray's attended sessions are launched from a terminal, the Desktop Code tab, or both — and whether that path differs from a routine's in any env or payload respect — is unmeasured. Step 0 modes A/B/C/D measure it; SD-3's option (a) is viable only if it differs.
- **R3 — Resume (G17, asserted-not-verified).** If a routine can resume a minted session, it inherits the token's residual TTL. SD-4 bounds it; Step 0 answers whether it can happen.
- **R4 — Stale worktrees.** A routine started in one of the 19 checked-out copies runs the hooks *that copy* has. Out of scope; PLAN-0122 AC-10's audit is the instrument.
- **R5 — `permissions.allow` in gitignored `settings.local.json`.** A local allow broader than `settings.json`'s does not weaken any hook (hooks run regardless of permission mode), but it can silence a prompt the recorder in Step 0 was meant to observe. Step 0 records the local allow list's **shape** alongside the modes.
- **R6 — The classifier transport is an unattended MS-S1 call by construction** (G4). This PLAN leaves it exactly where PLAN-0122 put it; if §8's boundary is ever read to cover it, that is a PLAN-0122 question.
- **R7 — The smoke record.** L-3's `handoff-reader` run is LOCKED but its durable record was not found in `docs/STATUS.md` at HEAD (G16). Code cites the transcript or log path at commit.
- **R8 — Threat surface not covered here:** `git` invoked through a non-`git` binary (`uv run python -c "import subprocess…"`), `gh` aliases, and PowerShell spellings. The regex family is the same one the repo already trusts for the actor axis; widening it is a follow-up with its own probe rows, not a silent addition.
