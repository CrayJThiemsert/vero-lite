## Goal

Give every load-bearing assertion an identity that is **declared by its author, lives on the assert's own line-above as `# claim: <id>`, and travels with the assert through any edit of its text** — so that a probe's `expect_claim` and an exemption's key stop rotting when `ruff format` reflows a literal or a setting is renamed, **can never be silently re-targeted onto a different assertion** (identity is carried, not inferred from a pattern over neighbours), and **need no second artifact** (no per-PLAN generator, no spec file, no repin cycle) to stay correct. The driver keeps addressing claims **only** by `Claim.stable_key` (PLAN-0115 AC-5 stays as written); what changes is that `stable_key` gains a second, author-declared derivation — `@<id>` for a tagged claim, `owner|source|#occurrence` for an untagged one — under the invariant **one claim, one key**. A `tag` subcommand migrates an existing text-keyed battery and **prints per-battery equivalence values** (`resolved_same=… resolved_differ=0`), never a bare PASS. The three PLAN-0126 story batteries migrate first; when they run green on tags, `tests/batteries/plan_0126_story_generator.py`, `tests/api/test_story_battery_generator.py` and `tests/batteries/s309-story-battery-generator.json` are deleted in the same PR. Four PRs (one contingent on SD-b), one PLAN, no ADR (SD-d).

## 0. Where this PLAN starts — the frontier

**Solved (do not re-do):** the driver addresses claims by an exact key and refuses everything it cannot address **before the first mutation** (`_validate`, `tools/probe_battery/_battery.py:327-344` ✔); the lint moves that refusal to commit time for every committed battery and is `always_run` because the rot is authored on the code side, never the battery side (`tools/probe_battery/_lint.py:14-22` ✔; `tools/check_battery_definitions.py:17-20` ✔); the coverage report names every claim that is neither reddened nor exempted, and calls an addressed-but-absent key STALE (`tools/probe_coverage.py:213-216`, `:226`, `:254-268` ✔); and the s309 interim generator resolves keys from `(owner, source-prefix)` with an exactly-one refusal (`tests/batteries/plan_0126_story_generator.py:113-122` ✔).

**Uncracked (this PLAN's work) — the dispatch's three requirements for an address:**
1. **Survives an assert's text changing.** Today's key *is* the text (`Claim.stable_key = f"{owner}|{source}|#{occurrence}"`, `tools/probe_coverage.py:96` ✔; `source` is the whitespace-normalised first 160 characters of the assert's test expression, `:162` ✔). Change the text, the key addresses nothing. The lint makes that **loud**, but the repair is a hand-typed key per probe, and s287 measured two batteries dead for a whole session before the lint existed (`_lint.py:3-13` ✔ — recorded there; not re-measured).
2. **Never silently re-targets onto a different assertion.** This is hazard **H1**, and it is where the obvious fix fails. A reference resolved from `(owner, prefix)` with exactly-one (the s309 generator's rule, `:115-122` ✔) has this failure: an owner asserts `result.error == "missing"` and `result.error == "missing" or retry`; delete the first, and the prefix `result.error ==` still resolves **exactly once — to the other assertion**. The battery keeps "witnessing" a claim nobody declared. The exact key fails loudly in the same situation. **Any address that is looser than the claim's own identity has this hole, and no rule over the *current* source can close it** — the information that the first assert *used to exist* is not in the current source. §2.4 works this through for every candidate.
3. **Needs no second artifact that can drift from the battery.** The s309 generator is that artifact: it lived outside git across s304–s305, STATUS named a stale copy as the only copy, and that copy produced **35** page probes against the committed **41** (⚠️ asserted-not-verified — s309 prose in the dispatch and in the generator's own docstring `:6-12` ✔ as text; a regeneration from it would have deleted the AC-11 and AC-3 witnesses without a word). The interim guard (`tests/api/test_story_battery_generator.py:42-59` ✔) makes that drift loud; it does not remove the artifact.

**The resolution this PLAN proposes:** requirements 1 and 2 are only jointly satisfiable if the identity is **carried by the assert itself** rather than **derived from its text or its neighbours**. A `# claim: <id>` comment on the line above the assert is exactly that: it survives any edit to the text (1), it is deleted with the assert and can be held by no other assert (2), and it lives in the one place that cannot drift from the code because it *is* the code (3). §2 is the design; §2.3 maps it onto H1–H4.

**Eliminated, not automated** (the dispatch permits this): **(E1)** the per-PLAN generator pattern — its only irreducible job was resolving intent to a key, and a tag *is* the intent written where the key is read. **(E2)** the `(owner, prefix)` exactly-one rule, in any form, including as a load-time reference — it is H1's mechanism, not its cure (§2.4). **(E3)** a "repin" subcommand that re-resolves stale text keys from a stored reference — it keeps a second field that must be validated in three places (hazard H2) and defends H1 only procedurally, by a human reading a printed diff (§2.4, direction b'). **(E4)** the interim `--check` guard (`plan_0126_story_generator.py:1008-1027` ✔) — once a key cannot rot, "does the generator agree with its output?" has no object.

**A hazard already present today, recorded so it is not rediscovered:** because `source` is truncated at 160 characters (`tools/probe_coverage.py:162` ✔), two untagged asserts in one owner that agree on their first 160 characters share a text key and are disambiguated by `occurrence` alone — so deleting the first silently re-points `#0` at the second. That is H1 inside today's exact-key scheme, for long asserts only. Tags close it too; nothing in this PLAN widens the truncation.

## 2. The design — claim tags

### 2.1 The grammar (one form, deliberately narrow)

- A **tag** is a comment line **immediately above** an `assert` statement or a `with pytest.raises(...)` / `pytest.warns(...)` header, at any indentation: `# claim: <id>`, where `<id>` matches `[A-Za-z0-9][A-Za-z0-9_./-]*`. The id cannot contain `|`, `#` or whitespace, so a tag key can never look like a text key.
- A tagged claim's `stable_key` is **`@<id>`**. An untagged claim's key is unchanged.
- Tags are read from **`tokenize` COMMENT tokens**, never from a regex over raw lines — a `# claim:` inside a docstring is a string, not a tag, and must not be reported as an orphan.
- **Placement is line-above only**, not trailing, for a reason that is in the code: `ast.get_source_segment` slices the file by position (`tools/probe_coverage.py:155` ✔), so a trailing comment on an interior line of a multi-line assert would enter `source` and change the *text* key of that very claim. A line-above comment never enters any segment, and `ruff format` preserves standalone comment lines in place.
- **Refusals at enumeration** (new `ClaimTagError`, a `ValueError` subclass): the same id on two claims of one module; a tag line whose next statement is not a claim (an orphan); a malformed id. All three are loud at `enumerate_claims`, so the lint (always_run) and the driver (before the first mutation) both see them.

### 2.3 How each dispatch hazard is met

- **H1 — silent re-target (the centre).** The tag is deleted with the assert. After the deletion in §0's example, `@E1` resolves to **nothing**: `_validate` refuses before the first mutation (`_battery.py:333-339`), the lint refuses at commit (`_lint.py:87-91`), and the sibling `result.error == "missing" or retry` cannot be chosen because it carries a different tag or none. The refusal is **structural** — no rule over the current source is consulted — and it is inherited from code that already exists; AC-2 witnesses it RED and replays the prefix rule on the same fixture as a closed-incident oracle (the PLAN-0115 AC-6 pattern, `0115:226-231`). The one way a tag *can* move to a different assert is a human cutting and pasting the comment line; that is caught at run time as a `MISFIRE` (the failure site is not the tagged line), exactly as a moved assert is caught today — not a regression, and AC-8's second case pins the live-lookup path that makes the site comparison correct.
- **H2 — two address forms coexisting.** There is **one field** (`expect_claim`) and **one lookup** (`stable_key` in the index). A tag key and a text key are two *derivations* of the same key, not two paths, so `_validate`, `_overlaps` and the lint cover both with no new code (§2.2) — AC-2, AC-6 and AC-7 each exercise the tag form through the *unchanged* refusal. What could reintroduce a second path is a reference-shaped field in the JSON; `Probe.from_json` now refuses those (AC-3). The end state SD-f proposes — every *addressed* claim tagged, text-form addresses refused by the lint — collapses even the two derivations to one at the address surface.
- **H3 — exemptions are addressed too.** `Battery.exemptions` keys are `stable_key`s (`_battery.py:233-240`), so an exemption is written as `"@<id>": reason`, the orphan check (`_lint.py:101-112`) reports a deleted tagged claim's exemption exactly as it reports a text one, and the `tag` subcommand migrates exemption keys alongside probe keys (AC-6, AC-9).
- **H4 — the coverage denominator.** `render_report(claims, credited, exemptions, key_of=stable_key)` (`_battery.py:644-646`) is unchanged; the denominator is still *every* claim enumerated from `claim_sources`, tagged or not, and a gap is still a claim in neither map (AC-7). Tags are required only for what a battery **addresses**; the denominator needs none, which is why coexistence costs nothing at the report.

### 2.4 Why each candidate direction loses to tags

- **(a) Reference resolved at load `{owner, prefix}` → key.** Reopens AC-5 directly (a second address form in the API) and has no structural answer to H1: after the deletion, the *only* fact that would refuse the sibling — that the declared assert once existed — is absent from the current source. Every mitigation is a heuristic (edit distance, claim-count deltas) that turns a loud failure into a warning someone must read. **Rejected for H1** (the dispatch's REJECT-if condition, restated in writing).
- **(b) Keep AC-5, repair rot with tooling.** The honest version (call it **b′**, a *lockfile*): each probe carries a pinned text key **and** a `(owner, prefix)` reference; the driver runs on the pin, a `repin` subcommand re-resolves the reference when the pin dies and prints `old → new` for review. H1 is defended, but only **procedurally** — the tool prints the sibling's text and a human must notice it is a different assertion — and the design adds a field that must agree with the pin in `_validate`, the lint and `repin` (H2's surface, three places). Tags defend H1 structurally with zero new refusal code. **Second choice**, offered in SD-a as the fallback if Cray rejects tags.
- **(c) Specs as native driver input.** The generator generalised: an alternate path by construction, and it inherits (a)'s H1 hole because its resolver is the prefix rule. **Rejected.**
- **(d) Status quo plus per-PLAN generators with guards.** Each generator is a second artifact with the s309 drift shape; the guard makes drift loud but every new generated battery adds one more artifact to keep honest. **Rejected** — it scales with the number of generated batteries, which is the dispatch's own objection.

### 2.5 The `tag` subcommand (migration and convenience)

`python -m tools.probe_battery tag <battery.json> [--dry-run]` — for every key the battery addresses (probe `expect_claim`s ∪ exemption keys): resolve it against `claim_sources` to a claim; if that claim already carries a tag, **adopt** it; otherwise choose an id (SD-e: default `<battery-stem>/<probe-name>` for the first probe declaring the key, `<battery-stem>/exempt-<k>` for an exemption) and plan a `# claim: <id>` line above the claim at the statement's indentation. **Compute the whole plan first, refuse before writing** if any key is unaddressable, any chosen id is already used in its module, or a target line-above already carries a *different* tag. Then write insertions bottom-up per file (so earlier line numbers do not shift), rewrite every addressed key to `@<id>`, re-enumerate, re-run `lint_battery_file` on the result, and **print** `battery=<name> addressed=<n> tagged=<n> adopted=<m> resolved_same=<n> resolved_differ=0` where `resolved_same` counts keys whose pre-rewrite resolution `(owner, source, occurrence)` equals the post-rewrite `@` key's resolution. A non-zero `resolved_differ` is a refusal (exit 2) and the files are restored from the in-memory originals. The proof is claim-identity equality, printed as values — with tags every *key string* changes by construction, so "keys_equal" would be meaningless; the dispatch's shape is honoured in substance (per-battery values, never a bare PASS).

### 2.6 Frame reconciliations (arguments this PLAN owes)

- **R-A — PLAN-0115 AC-5 is kept, not reopened.** AC-5 says the driver addresses claims *only via `Claim.stable_key`* and that no alternate keying path exists in the API (G4). Both remain literally true: `expect_claim` is the only field, `stable_key` the only lookup, and the s253 defect (a hand-rolled key beside the imported one) cannot recur because no caller computes a key. What changes is the **derivation** of `stable_key` for tagged claims, and the AC-5 fixture (two identical asserts in one owner, G22) stays green (AC-5 below re-asserts it with one twin tagged). SD-a still asks Cray to confirm this reading, because the dispatch framed the work as reopening AC-5 and the ruling is Cray's; the reversal cost of the *alternative* is stated there.
- **R-B — a tag is not battery metadata leaking into tests.** CLAUDE.md §8 makes the *load-bearing assertion* a first-class object; §4 says a gate or tripwire must live on a tracked, scanned surface. A `# claim:` line names the load-bearing assertion where it lives, on the surface the lint scans at every commit. It is the §8 discipline's own vocabulary written down, and it is visible to the reviewer of any diff that touches that assert.
- **R-C — the driver stays an instrument.** Nothing here runs a battery anywhere but by hand; the lint (already `always_run`) is the only commit-time actor, and it only gains a third refusal class (tag integrity). ADR-0038 D2-C1's line (G14) is untouched.

- **SD-a — reopen PLAN-0115 AC-5, or keep it?** *Options:* (i) **keep AC-5 as written and adopt tags** — `stable_key` stays the only address, with an author-declared derivation (§2.6 R-A); (ii) reopen AC-5 with a load-time `(owner, prefix)` reference (direction a); (iii) keep AC-5 and adopt the lockfile b′ (§2.4). *Drafter's recommendation:* **(i)** — it is the only option that meets H1 structurally, adds no refusal code, and leaves AC-5 (`0115:222-225`, `:323-324`) and the CLAUDE.md §8 sentence ("`Claim.stable_key` addressing … live in the tool") literally true. *Reversal cost of (ii), stated as the dispatch requires:* every one of the **50** committed batteries (G15) and their **~623** probes (G16, ⚠️) is addressed by a text key that would become a second form beside the reference; `_validate` (`:327-344`), `_overlaps` (`:347-360`), the lint (`:74-125`) and `render_report` (`:218-226`) would each need to see *resolved* keys; the s253 defect class — a key computed beside `stable_key` — reopens by design; and refusal 3 (`_battery.py:30-32`), README row 3, PLAN-0115 AC-5/Step 5 and the §8 sentence would all need rewording. Under (i) none of the 50 batteries has to change (coexistence), no refusal changes, and the constitution sentence stands. *Why Cray's:* the dispatch and the s309 ruling framed this work as "reopens AC-5"; whether R-A's reading — *derivation changed, address unchanged* — satisfies that ruling is a governance call, not a code fact.
- **SD-b — migration of the 47 batteries that are not PLAN-0126's.** *Options:* (i) **additive coexistence, migrate on rot** — a text key that dies is repaired by tagging that claim (`tag` on that battery), so migration proceeds one battery at a time as the lint reddens them; (ii) **one bulk PR via `tag`** with the printed per-battery and aggregate proof (Step 4, AC-11); (iii) opt-in per battery with no schedule. *Drafter's recommendation:* **(ii)**, as Step 4, in its own `chore/*` PR *after* Step 3 has proven the tool on three batteries — because leaving two derivations in the tree indefinitely keeps H2's reviewer-side cost alive, and the tool makes the bulk cheap and provable. *Cost to weigh:* the PR touches every test module any battery addresses (comment lines only, ~600 by G16) and will conflict textually with any concurrent branch editing those modules — sequence it in a quiet window. *Why Cray's:* it is a tree-wide diff across modules other streams own, and the equivalence proof is a review Cray reads.
- **SD-c — does the CLAUDE.md §8 sentence need rewording?** *Options:* (i) **no change** — "`Claim.stable_key` addressing" remains true under tags; (ii) a parenthetical naming the tag form so a reader of §8 learns the convention there. *Drafter's recommendation:* **(i)** now; revisit (ii) only if SD-f rules (iii), when "tagged" becomes the sole address form for what batteries declare. The drafter's candidate wording for (ii) is in its dispatch return, flagged as a separate constitutional edit, and is deliberately absent from this PLAN. *Why Cray's:* constitutional.
- **SD-d — is an ADR warranted, or does this PLAN amending a done PLAN's AC suffice?** *Options:* (i) **no ADR** — this PLAN records the amendment in §2.6 R-A, and Step 5 adds a one-line pointer under PLAN-0115 AC-5 in `docs/plans/done/` ("derivation extended by PLAN-0128; the address and the refusal are unchanged"); (ii) an ADR making "one claim, one key; identity travels with the assert" a binding rule for every test author, since no ADR names `stable_key` today (G9). *Drafter's recommendation:* **(i)** — the change is to an instrument's key derivation, PLAN-0115 itself was a PLAN, and the §8 sentence already carries the binding half at constitution tier; an ADR would bind test authors to a convention the lint already enforces mechanically. *Why Cray's:* whether the tag convention should be constitutional-tier is precisely the kind of promotion ADR-0038's three-strike rule exists to decide.
- **SD-e — the id scheme the `tag` subcommand writes.** *Options:* (i) **`<battery-stem>/<probe-name>`** for a probe-addressed claim and `<battery-stem>/exempt-<k>` for an exemption — unique across batteries by construction, readable in a diff, and a probe's name is already the reviewer's handle; (ii) `<owner>-<k>` — shorter, module-local, but two batteries tagging the same module can collide and a `k` is a position; (iii) hand-named ids, with `tag` refusing to run without a mapping file. *Drafter's recommendation:* **(i)**, with hand-editing of any id allowed afterwards (the key is whatever the comment says). *Why Cray's:* the ids are what every future battery diff shows the reviewer.
- **SD-f — the policy for addresses after this PLAN.** *Options:* (i) tags recommended, text keys allowed indefinitely (coexistence); (ii) tags **required for new batteries** — unenforceable, because the lint cannot tell a new text key from an old one; (iii) **after SD-b's bulk migration, the lint refuses any text-form address** (`|#` in an `expect_claim` or exemption key), so every addressed claim carries a tag and the address surface has one form (Step 4's second bullet). *Drafter's recommendation:* **(iii) if SD-b = (ii), else (i)** — never (ii). *Why Cray's:* (iii) is a standing rule for every future battery author, which is a Cray ruling, not a Code default.
