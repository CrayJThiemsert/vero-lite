This PLAN makes an execution-derived fact travel as a **tool-emitted `measure` block** (ADR-0038's own vocabulary, sealed with a content hash), gives the two writers a contract that lets them write ✔ only from such a block or from a file they re-read, and ships the staleness guard ADR-0038 ratified as *"owed work, not an option"* — the guard that reads the `against-SHA` field nobody reads today.

## Goal

Ship the mechanism ADR-0038 D3 ratified and left ownerless (OQ-5): a `measure` artifact that a **tool** emits — value, procedure, `against-SHA`, `declared-paths`, who/when, a predicate fixed before the number was taken, a per-instance positive control, and a content hash — so that a model-typed number is *detectable* rather than merely *discouraged*; a **fact-pack contract** under which `status-scribe` and `plan-drafter` may write a fact as ✔ only if it arrived as such a block (execution facts) or they re-read it themselves (file-content facts), writing everything else `⚠️ asserted-not-verified` with the reason; and the **staleness guard** that walks a populated surface at pre-commit, recomputes each block's hash, runs `git diff --name-only <against-SHA>..HEAD -- <declared-paths>`, re-runs the procedure where that is possible offline, resolves every citation, and **prints the values it measured**. The uncovered class — behavioural claims about how the harness *acts* — is named in §5 and is not covered by anything here.

## 2. The block — schema and emitter (② — the main Code agent measures)

### 2.1 Vocabulary is ADR-0038's

| ADR-0038 term | Where the ADR defines it | JSON key in the block |
|---|---|---|
| `measure` (the kind) | `0038:524-525` | `"schema": "measure/v1"` |
| value / units / procedure | `:505-506`, `0108:88-89` | `value`, `units`, `procedure` |
| `against-SHA` | `:516`, `:556`, `:582` | `against_sha` |
| `declared-paths` (*"which paths it measured"*) | `:580` | `declared_paths` |
| who / when | `:555` | `who`, `when` |
| pre-fixed predicate (*"a pass predicate fixed before the number was taken"*) | `0108:89`, `0038:555` | `predicate`, `pass` |
| positive control, per instance | `:560-570` | `control` |
| re-runnable procedure | `:505-506` | `rerun` (bool: may the guard re-execute it offline) |

The JSON keys are the ADR's terms in snake_case — the same words, one spelling that a parser can hold. This PLAN adds exactly **two** fields the ADR does not name, both mechanical: `hash` (the seal — dispatch §4.2) and `history` (§2.3 — a measurement over an immutable commit range has no paths to declare). A third schema, a renamed field, or a "provenance stamp" that is not this block is a defect (dispatch §4.1).

### 2.2 What a block looks like

The block is a fenced JSON object preceded by a marker line, so a parser finds it by the marker and a human reads it as-is. **The values below are illustrative** — the shape is binding, the numbers are not (the real first blocks are AC-5's, emitted by the tool):

```
<!-- measure:v1 -->
```json
{
  "schema": "measure/v1",
  "metric": "status_bytes",
  "value": "58401",
  "units": "bytes",
  "procedure": {"file": "docs/STATUS.md", "reduce": "bytes"},
  "against_sha": "f65f7ea000000000000000000000000000000000",
  "declared_paths": ["docs/STATUS.md"],
  "history": false,
  "who": "code-s291",
  "when": "2026-09-10T03:31:07Z",
  "predicate": "value <= 65536",
  "pass": true,
  "control": {"file": "docs/plans/0000-template.md", "reduce": "bytes", "value": "412"},
  "rerun": true,
  "hash": "sha256:0f3c9a1b2e4d5f60"
}
```
```

**`against_sha` is the full 40-hex SHA** (s299 — the s291 draft said `--short=7`; the value above is illustrative, padded to length). A short prefix is not immutable: it can become ambiguous as the repository grows, and a seal over an ambiguous prefix is a seal over a moving reference. The full form is also what `tools/_evidence.py`'s `head_sha()` records (`:71-90`, G39) and what a goal's `declared_head` carries (ADR-0018 A4-2, G43), so the two SHA-provenance mechanisms print one shape. The `MEASURE:` line prints it in full too — one form, no abbreviation to reconcile. (STATUS's own `head_commit` field stays the short SHA it has always been — `docs/STATUS.md` frontmatter — because that is a STATUS convention, not a block field; §2.3's recipe says so explicitly.)

**JSON, not YAML — derived, not chosen:** every guard in `tools/` is stdlib-only (G12, G33), the pre-commit hooks run under `uv run --no-sync`, and a hash needs one canonical byte form — `json.dumps(obj, sort_keys=True, separators=(",", ":"))` is that form; YAML has several.

**The seal.** `hash` = `sha256:` + the first 16 hex characters of SHA-256 over the canonical JSON of every field *except* `hash`. Any edit to any field — a re-typed value, a "corrected" date, a dropped control — changes it, and the guard recomputes it before doing anything else (§3.2). What the seal is and is not: it detects a block that a **model typed** (a model has no way to compute it) or a human **hand-edited**; it is not a signature — an actor with a shell can re-seal. The threat this PLAN closes is the first one, because that is the actor who writes the most numbers and cannot run the tool (§1 G1–G3).

**The citation token.** A tracked artifact cites a block as `measure:<16-hex>` (the hash without its `sha256:` prefix). The guard resolves every token against the blocks it parsed (§3.3). A token with the suffix `:historical` means *"true at `against_sha`, cited as a past-state reading, not as a live premise"* (§3.4 — whether that qualifier exists at all is SD-7).

### 2.3 The emitter — `tools/measure.py` (SD-4 = a+_evidence, Cray typed s299: a new module built on `tools/_evidence.py`)

One invocation, one block. **No shell, ever** — the procedure is an argv list run by `subprocess.run([...], shell=False)` (Lesson #0007; the same idiom as `_status_lint.py:109-116`), or a file reduction with no subprocess at all.

```
python tools/measure.py --metric status_head_range_commits --units commits \
    --history --predicate "value == 9" --who code-s299 \
    --control-argv "git log --format=%h 793b9d9..793b9d9" --control-reduce lines \
    --reduce lines -- git log --format=%h 793b9d9..f65f7ea

python tools/measure.py --metric status_head_drift --units commits \
    --history --predicate "value == 3" --who code-s299 \
    --control-argv "git log --no-merges --invert-grep --grep=^docs(status): --format=%h 793b9d9..793b9d9" --control-reduce lines \
    --reduce lines -- git log --no-merges --invert-grep --grep=^docs(status): --format=%h 793b9d9..f65f7ea

python tools/measure.py --metric status_bytes --units bytes \
    --paths docs/STATUS.md --predicate "value <= 65536" --who code-s291 \
    --control-file docs/plans/0000-template.md --control-reduce bytes \
    --file docs/STATUS.md --reduce bytes
```

✎ **s299 — the first example was renamed, and the second added** (`was an error (unit)` in the s291 metric name — this is where the classification lives, with SD-1's premise; G15's row measured the total correctly and is `confirmed — prior intact`). The s291 draft ran the first procedure (every commit in the range, merges included) under the metric name `status_head_drift` with `value == 9`. That number is a **total** — the range holds 9 commits, 5 of them merges — while ④-lite's `drift` counts **substantive** commits only (`--no-merges --invert-grep --grep=^docs(status):`, `_status_lint.py:89-105`, G45), which were **3**. The reviser chose to **rename** rather than change the first procedure, because a total-commit count is a legitimate measurement (it is G15's `rev-list --count` reading) that simply must not wear the guard's name; the second example measures what `drift` means under the guard's own filter, so SD-1's premise number can become a block. The values: **✔ (Code, s299)** — re-run at `main` `7b92f3d`, procedure: `git rev-list --count 793b9d9..f65f7ea` = 9 (5 merges); `_git_substantive_shas(root, "793b9d9..f65f7ea")` = 3 (empty-range control = 0). **Reducers** replace the pipes a shell would need: `raw` (stdout stripped) · `lines` (non-blank line count) · `bytes` (byte length of the file or stdout) · `first` (first line) · `int` (stdout must parse as one integer) · `count:<regex>` (occurrences of a pattern — the G16 needle shape, and the reducer whose *unit* is named so lines-vs-occurrences cannot recur silently).

**What the emitter records without being told:** `against_sha` = the full `git rev-parse HEAD`, taken by the emitter's **own** call and refused on failure (R8 — s299: the s291 draft said `--short=7`, see §2.2; and it does **not** go through `tools/_evidence.py`'s `head_sha()`, whose fallback is the value `"unknown"`, `_evidence.py:64-68`, `:87-90` — right for an evidence stamp that must never lose a reading, wrong for the one field the guard's oracle rests on); `when` = UTC now; `who` from `--who` (required; defaults are how a field becomes decoration); `pass` = the predicate evaluated over `value`; `control.value` = the control procedure's own reading.

## 3. The guard — `tools/check_measure_staleness.py` (④ — OQ-5, discharged)

### 3.1 Why this is not the vacuity gate ADR-0038 refused

`0038:266-271` refuses a mechanical **vacuity-detector** for C1 because such a gate *supplies its own oracle* — the author writes the rule that says what "vacuous" looks like, and #0039's finding is that a self-authored guard inherits its author's blind spot. This guard supplies **no oracle of its own.** Every fact it acts on was declared by the *artifact*, and every fact it checks against was produced by *git*: the SHA the block declares, the paths the block declares, the procedure the block declares, and the tree as git reports it at HEAD. The guard asks git one question — *did any declared path change between the declared SHA and now?* — and, where the artifact's own procedure is re-runnable, asks the procedure a second — *does it still say what the block says?* It cannot be talked into a verdict about a fact it was not handed, and it cannot be wrong about a fact in a way the author's imagination shaped, because the only thing the author wrote is the diff invocation, which is the one the ADR itself spelled out (`0038:582`). The residual risk is the parser and the invocation — and those are the two things the guard's positive controls exercise on known-bad content before any real reading is trusted (AC-6, AC-9; CLAUDE.md §8 *"an instrument whose reading you will act on passes a control on known content"*).

And this is not a re-litigation of the refusal: **OQ-5 is the ADR's own ratification of exactly this mechanism** — *"the artifact's declared-paths field plus the `git diff --name-only <against-SHA>..HEAD -- <paths>` check that marks a `measure` artifact stale. Ratified as required, so this is owed work, not an option"* (`0038:758-764`). The ADR refused a gate that judges *quality* and required a guard that computes *freshness*. This PLAN builds the second.

### 3.2 What it does, in order

1. **Walk the block surface** — `docs/logs/*.md` (ADR-0038 D3's ratified home, G10). Parse every `<!-- measure:v1 -->` block. `blocks=N`. **If `N == 0` the guard exits 1** with `blocks=0 — EMPTY SURFACE, NOT a pass`: the null-glob shape PLAN-0108:104-109 refused to build, made into a red instead of a silent green (the `_GUARD_FLOOR` precedent, G14).
2. **Recompute every hash** → `hash_bad=N`. A bad seal gates (exit 1). A block that fails to parse as JSON counts here too — the `tally.py:97-104` rule (✎ `line drift` from `:83-90`, G35) that a skipped record is how a breakdown stops describing its input.
3. **Resolve `against_sha`** (`git rev-parse --verify --quiet <sha>^{commit}`). Unresolvable in a **shallow** repository (`git rev-parse --is-shallow-repository` = `true`) → `unavailable=N`, printed, not gated — the ④-lite idiom (`check_status_freshness.py:29-32`), a *visible* skip. Unresolvable in a full repository → `unresolvable=N`, a broken pointer, gates.
4. **Staleness** — for path blocks: `git diff --name-only <against_sha>..HEAD -- <declared_paths>`; non-empty → `stale=N`. History blocks (`history: true`) are immutable by R5 and skip this step.
5. **Re-derivation** — for `rerun: true` blocks that are **not stale** (a stale block's re-run is uninformative: the paths moved), and for every history block: re-execute the procedure at HEAD, apply the reducer, compare to `value` → `rerun=N mismatch=M`. A mismatch on unchanged paths means the recorded number was **never true** — `0038:513-514`'s first laundering shape, *"a number nobody took"* — and gates.
6. **Citations** — walk `docs/plans/*.md` (not `done/`), `docs/STATUS.md`, `docs/adr/*.md` for `measure:<16hex>` tokens → `cites=N`; a token with no block → `dangling=M`, gates. A live token whose block is stale → `stale_cited=K` (gating is SD-7). `:historical` tokens are counted (`historical=N`) and never gate on staleness.
7. **The honest marker** — count `⚠️ asserted-not-verified` occurrences in active `docs/plans/*.md` → `asserted=N`. **Printed, never gated** (§6 E6).
8. **Print** — `MEASURE-STALENESS: files=F blocks=N hash_bad=a unresolvable=b unavailable=c stale=d rerun=e mismatch=f cites=g dangling=h stale_cited=k historical=i asserted=j elapsed_ms=t` — every run, `verbose: true`, so the numbers are seen on each commit and not on the day someone is surprised.

**Exit:** 1 on `blocks == 0`, `hash_bad > 0`, `unresolvable > 0`, `mismatch > 0`, `dangling > 0`, and `stale_cited > 0`; otherwise 0. The last term is **SD-7 = (b), Cray typed s299**, wired as `GATE_STALE_CITED = True` (Step 2.1) — a constant so the ruling is legible in the source, not so it can be quietly flipped. _[s291 wording, kept: "and — under SD-7 (b) — `stale_cited > 0`".]_

### 3.4 A stale *reading* is not a stale *premise*

ADR-0038 says a stale `measure` artifact is INSUFFICIENT-EVIDENCE, never PASS (`0038:583-584`) — for a **criterion closing on it**. A grounding row that records *"the range `793b9d9..f65f7ea` held 9 commits"* — or *"drift was 3 at `f65f7ea`"*, the substantive count (✎ s299 R2, `was an error (unit)`: the s291 sentence read *"drift was 9"*, the same total-vs-substantive slip SD-1's premise records; both numbers ✔ (Code, s299), G15) — is a reading of a past tree; the decision it supports does not need the number to be current, only to have been true. _[s291 wording, kept: *A grounding row that records "drift was 9 at `f65f7ea`" is a reading of a past tree.*]_ Treating that as a defect would either gate every commit that moves `main` (the over-refusing shape, G14) or teach authors to stop citing blocks — the laundering incentive in reverse. Hence the `:historical` qualifier and the split between `stale` (printed) and `stale_cited` (a live premise that moved — **gates, SD-7 = (b), Cray typed s299**).

**The precedent, found s299 (fact-check).** The goal gate already draws this line one level up: ADR-0018 A4-1 (`docs/adr/0018-axis-b-verification-loop.md:1718-1723`, #1482 — G42) makes `contended` and `basis-moved` states that are *"about the basis, not the work: never a defect in the trail, never a ladder rung, never `passed`"* — exactly the stale-*reading*/stale-*premise* distinction above. A4-2 (`:1724-1734`, G43) makes `basis-moved` **declarative**: it exists only when the goal carries `declared_head` and HEAD has moved past it, with detection OFF when no head was declared. That is the goal-level sibling of the block-level `against_sha`: two SHA-provenance mechanisms now coexist by design — whole-tree `declared_head` on a *goal*, path-scoped `against_sha` on a *block* — and neither infers the other. The asymmetry A4-2 keeps (a tree-basis check that fails after HEAD moved stays `fail`) is the one §3.2 step 5 keeps: a re-run mismatch on *unchanged* paths is a defect, not a basis move.

## 4. The fact-pack contract (③ — the writers)

The contract lives **in each writer's own prompt** — CLAUDE.md §4's placement rule (`CLAUDE.md:86`): *"A rule meant to bind an automated judge or enforcer — a classifier, a hook, the `goal-evaluator` — must live in that enforcer's own input surface; written anywhere else it is, for that consumer, not written."* (✎ s299: the s291 quote dropped the clause *"— a classifier, a hook, the `goal-evaluator` —"* with no ellipsis; restored, re-read.) It is small by design (dispatch §4.7).

### 4.1 `plan-drafter` (`.claude/agents/plan-drafter.md`)

Grounding-table marks become a closed set of four:

| Mark | Written only when |
|---|---|
| `✔ <file:line>` | the drafter **re-read** the cited line (file-content fact) |
| `✔ measure:<16hex>` | the drafter **Read the block** in the named `docs/logs/` file and copied `value` and `hash` from it (a file-content act — the drafter cannot verify the seal; the guard does) |
| `✔ measure:<16hex>:historical` | as above, cited as a past-state reading (§3.4) |
| `⚠️ asserted-not-verified — <reason>` | everything else — including *"block present in the dispatch/handoff only, not persisted to `docs/logs/`"* (SD-2) |

An execution fact with no block is **never ✔** — the rule the drafter's `:136-153` clause already implies, now with the mechanism that makes it satisfiable. Dispatch payload: `scoped_context.measures` names the `docs/logs/` file(s) carrying the blocks; the drafter Reads them.

### 4.2 `status-scribe` (`.claude/agents/status-scribe.md`)

Two payload fields change type, nothing else: `head_commit` and `recent_commits` arrive as **`measure/v1` blocks** emitted by `tools/measure.py --recipe status-reconcile` (§2.3). The scribe transcribes each block's `value` into the frontmatter and **refuses** — the same refusal it already has for a missing field (`:100-104`) — when either arrives as prose, a bare SHA, or a block without `schema`/`hash`. The blocks are **not persisted** into STATUS (§6 E1 — ④-lite re-derives `head_commit` itself). `what_shipped` stays Code-attributed prose the scribe transcribes without vouching (§6 E2). Cost: two blocks ≈ 700 B of payload; zero extra turns.

### 4.3 `explore-research` (`.claude/agents/explore-research.md`) — SD-6

The dispatch's ③ asks this agent to *"produce the same block shape for file/web facts."* It cannot: it has no tool that runs `tools/measure.py` (G3), so any block it wrote would be **model-typed** — prose with extra fields, the exact thing dispatch §4.2 forbids; and a seal Code applied afterwards to a model-typed value would launder it (`0038:511-513`). The drafter's recommendation (SD-6 b), **now ruled (b) — Cray, typed, 2026-09-14, s299**: no block. A file-content finding is cited `file:line` and the consumer re-reads it (✔ by its own act); a web finding is always `⚠️ asserted-not-verified (web: <URL>, fetched <date>, excerpt: "…")` — honest about the one class nobody in the repo can re-derive offline. Web access stays with `explore-research` alone (Cray, typed, s291).
