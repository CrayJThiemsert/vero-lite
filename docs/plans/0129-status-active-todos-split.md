## Goal

Move the **entire** `## Active TODOs` section — every one of its `- [ ]` rows, byte-identical — out of `docs/STATUS.md` into a new **second Tier-1 state file**, `docs/TODOS.md` (SD-1), under the **same** `## Active TODOs` heading; leave a **forwarding stub section** in STATUS under that heading (the s171 "Update Workflow" precedent already in the file) so every one of the 124 section-name citations still resolves without a single frozen archive, archived PLAN or Accepted ADR being touched; put the new file into `CLAUDE.md` §9's read order **beside STATUS, not behind a link** (Cowork-drafted, committed in the same PR as the move, so the file never exists outside the read order); and make every tool, hook, agent and skill that reads STATUS by path read **both** surfaces through **one** shared surface list — so a row that carries a gate or tripwire is on exactly the surfaces it is on today, plus the one ranker that never read it. The section's rotation rules (R2's Active-TODOs extensions, the carve-out, R4) travel with it verbatim; the new file gets its own R1-class byte ceiling (SD-4) and its own line in the scribe's rotation report. Three PRs, one Cowork dispatch, no ADR. Nothing in this PLAN trims, retires or reorders a row: the move commit is a pure carve whose only proof is byte identity (§2.3), and row triage stays a reconcile-time R2 activity before or after it.

## 0. Where this PLAN starts — the frontier

**Settled (not reopened):** Cray's s276 direction — split Active TODOs into its own file — recorded in `docs/STATUS.md` §"Active TODOs", the row headed *"CRAY'S DIRECTION (s276) — SPLIT Active TODOs into its own file"* (✔ read by title). Its two fixed constraints: the file goes into `CLAUDE.md` §9's read order, not behind a link, because the hop is unreliable by measurement (Lesson #0034; `docs/for_llm/` holds only its README — §1 G32); and the guards that read STATUS are widened so a moved row cannot escape them.

**Unsolved — the seven questions the dispatch hands over, each designed below or surfaced in §8:** (1) path and what moves → §2.1, SD-1, SD-2; (2) a gate/tripwire row stays on a scanned surface → §2.4; (3) each guard that must read the new file, through one reader → §2.2; (4) the scribe route and the reconcile loop across two files → §2.5, SD-3; (5) R1/R2 for the new file → §2.6, SD-4; (6) citer migration, live vs archival, and the two ADRs → §2.7, SD-5, SD-6; (7) the CLAUDE.md §9 step, routed to Cowork → §2.8, SD-7.

**The three blockers, and what each dissolves under:**
- **Blocker 1 (124 section-name citers in 42 files; no guard can see a break).** Dissolves under the **stub**: a citation of the form `docs/STATUS.md §"Active TODOs"` names a *section*, and the section survives — as a one-paragraph forward to the new file, under the same heading. Nothing becomes a dead pointer, so there is nothing for a guard to see. What remains is *accuracy* drift in live prose, handled by class in §2.7. The dispatch's question — must archival citers change? — is answered **no, and they must not**: `docs/status-archive/` and `docs/plans/done/` are move-only frozen history (R4; the R7 and R8 allowlist rationales, §1 G22, G25), and the stub is what makes leaving them correct rather than merely convenient.
- **Blocker 2 (guards that read STATUS by path).** Dissolves under **one reader**: a single `STATE_SURFACES` tuple and a single line iterator in `tools/_status_surfaces.py`, consumed by every guard that reads STATUS content. Section-agnostic readers stay section-agnostic — they simply read two files — which is the property that lets `find_status_mismatches` keep its `CLOSED` count after the move (AC-2) instead of silently losing four of five tokens.
- **Blocker 3 (the hop).** Dissolves under the §9 read order, committed **inside the move PR** (SD-7), plus the two consumers §1 measured as not reading the section at all: `next-work-analyst` gathers candidates from STATUS frontmatter and Current Focus and never names Active TODOs (G16), and `stream-status`'s self-check greps `docs/STATUS.md` alone for two row titles that are both Active-TODOs rows (G17) — after a bare move that check prints `hits=0` for both and calls them dead pointers. Both are Tier-2.6 derived artifacts Code may edit; both are fixed in PR-2.

**Eliminated, not automated** (the dispatch permits this):
- **(E1) A per-class split** — moving PLAN rows and gates but leaving `CRAY'S CALL` rows in STATUS, or the reverse. It re-creates the exact hazard Lesson #0034 measured: *"a shared status with an unshared location is the tell"* (`:31-33` ✔). One list, one file, one grep target.
- **(E2) A citation-rewrite sweep** across the 42 files. R4 forbids it for archives, G1 forbids it for the two ADRs, and the stub makes it unnecessary everywhere else.
- **(E3) A second parser per guard** — a `find_todos_mismatches` beside `find_status_mismatches`, a second regex beside `CITATION_RE`. The s298 measurement that a second, stricter parser of the same shape left Check 3 blind is recorded in the docstring of `_own_text` in `tools/check_ac_consistency.py` ✔ (the dispatch attributed it to PLAN-0128, which dates from s309 — *was an error in the s317 dispatch*) — every consumer here reads through one iterator instead.
- **(E4) Row triage in the move commit** — retiring append-only rows into `docs/logs/` (as s312 did for the specimen ledger) *while* moving. It is real work and the R2 carve-out path already exists for it (rehome → re-point → verify → trim, `memory-architecture.md:306-307` ✔), but folding it into the move destroys the move's one proof: that the bytes removed from STATUS equal the bytes added to TODOS. Triage before, or after; never in the same commit.
- **(E5) Editing ADR-0013 / ADR-0035** to re-point their eight section-name citations. G1-gated, and under the stub they resolve. Queued with the R8 `docs/adr/**` temporary exemption's own repair list (§2.7, SD-5).
- **(E6) A third subagent (`todos-scribe`)** — one more hook, one more allowlist, one more identity route, for a file whose reconcile is the *same* transaction as STATUS's. The scribe route is SD-3.

**A premise this PLAN corrects on the way in (superseded by new info, not an error):** the s276 row's `:295-320` pointer is stale; the function is `find_status_mismatches` in `tools/check_ac_consistency.py` ✔ (G6). This PLAN cites that file **by symbol**, never by line, because an in-flight Check-3 change shifts its line numbers. And a finding the drafter did not expect, stated openly because it bears on SD-4: **the split does not reduce what a session reads at start** — STATUS (~20.6 KB after) plus TODOS (~41.8 KB) is the same ~62 KB the reader reads today (arithmetic on G1, ⚠️). What the split buys is structural: STATUS's rotation window stops being forced to ONE by a section that is not rotated (the s316 ledger's own diagnosis, ✔ read), the TODO list gets a budget of its own, and the ranker that never read the list starts reading it.

## 2. The design

### 2.1 Two Tier-1 surfaces, one heading, one stub

- **The new file is `docs/TODOS.md`** (SD-1): a sibling of `docs/STATUS.md` at the same level, upper-case like the two files the reader already opens first — the name is the signal that it is *always-read state*, not Tier-2 reference. Shape, top to bottom: an H1 (`# vero-lite — Active TODOs`), a two-line preamble stating what it is (Tier-1 volatile state, read every session after STATUS per `CLAUDE.md` §9; rules in the runbook's R1′/R2; never cite it by line number — R7 covers it, §2.2), and then **the section itself under its original heading `## Active TODOs`**, rows byte-identical to the carve. **No frontmatter**: nothing reads one (G10 — the freshness guard reads STATUS's `head_commit`; the handoff and stream skills read STATUS's `session`), and a second `head_commit` would be a second thing to keep true by hand.
- **The heading is retained on purpose.** Every section-name citation in the repo names `§"Active TODOs"`; Lesson #0034's rule 2 and its detection heuristic name `## Active TODOs` (G19). With the heading retained, each of those sentences stays literally true of the new file — the only thing that changes is which file the heading is in, and the stub answers that.
- **STATUS keeps a forwarding stub under the same heading** (SD-6), following the Update Workflow precedent already in the file (G20): one short paragraph — *moved on <date> (session <N>, PLAN-0129) to `docs/TODOS.md` §"Active TODOs", byte-identical, rules unchanged; this stub holds no rows and exists so every `docs/STATUS.md §"Active TODOs"` citation still resolves; new rows go there, never here.* The stub must carry no `- [ ]` line and no `AC-N … CLOSED` pair (it is on Check 2's surface); PR-2's guard (§2.2, `check_status_surfaces.py`) refuses a row written into it.
- **All 58 rows move** (SD-2). The alternative — a class split — is E1. A row the dispatch invites this PLAN to *retire* rather than move (an append-only record, a discharged call) is retired by the R2 carve-out path in its own reconcile, not in the move commit (E4). The three rows *about* the split are handled at closeout (AC-12, SD-8), after the move has proven itself.

### 2.3 The move itself — R6's method, applied to a carve

The move is a two-file transaction with the same failure shape R6 names (`:527-537` ✔): half-applied, both files individually well-formed, history silently lost. So it follows R6's method exactly, and its proof is printed, not asserted:

1. **Identify the slice** in `git show HEAD:docs/STATUS.md`: from the line `## Active TODOs` to the line before the next `## ` heading. Take its first and last rows **from that same `HEAD` text at execution time** — rows rotate, and the first row at draft time may have been discharged by then — print both, and assert both before anything is written; a mismatch aborts with nothing written.
2. **Carve the payload from `HEAD`**, never from any agent's returned text (R6 clause 1, `:543-555` ✔). Print `rows=<n> bytes=<n> sha256=<hex>` of the carved section.
3. **Write** `docs/TODOS.md` = preamble + the carved section, verbatim; **replace** the section in `docs/STATUS.md` with the stub.
4. **Verify positively in both directions** (R6, `:534-537` ✔): the section as it now stands in TODOS hashes to step 2's value; STATUS's `## Active TODOs` section holds 0 `- [ ]` rows; TODOS holds `rows=<n>` of them (58 at G1 — whatever the count is on the day, the two readings must agree); `CLOSED` tokens = 4 in TODOS + 1 in STATUS (G1's split, re-measured); STATUS bytes before and after, printed. All six values go in the PR body.
5. **No row is edited.** The diff of the two files, concatenated in read order, is a pure move plus the preamble and the stub. A reviewer can read it as such; that is the point of E4.
