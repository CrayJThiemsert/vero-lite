# s277 contention artifacts — the closed-incident pin for PLAN-0121

These five files are a **real pytest run's output**, captured in session 277 (2026-09-04)
while measuring what the probe battery does when the pytest child it spawned is cut off
before reaching a verdict. They are the `(b)` half of PLAN-0121 SD-4: the *live* shapes
generated by `tests/tools/test_probe_battery_contention.py` pin the present; these pin the
incident. A drift detector compares the two — when they part, the structural layer
(PLAN-0121 §4.3(2)) has gone dead while the exit-code layer still holds.

Hand-written junit XML stays forbidden (`tests/tools/test_probe_battery.py:1-15`). These
are not hand-written; every XML file here came out of pytest.

## The recipe

DB-free and deterministic — no database, no advisory lock, no `tests/db_guard.py` (which
does not exist; PLAN-0121 B20). A `pytest.exit(REASON, returncode=75)` reproduces the
shape a contended session would produce, without inducing contention.

```python
REASON = "TEST-DB-GUARD outcome=CONTENDED holder_pid=424242 db=vero_lite_test_s277"
```

Run under the battery's own argv, verbatim from `tools/probe_battery/_battery.py:363-372`:

```bash
python -m pytest test_trivial.py::test_a_db_backed_case \
  --junitxml=junit.xml -p no:cacheprovider -q
```

| stem | where `pytest.exit` fired | source |
|---|---|---|
| `s277_exit75_body` | the **test body** — `pytest.exit(REASON, returncode=75)` as the first statement | `/tmp/s277_p2body/test_trivial.py:10`, driver `run.sh:6-7` |
| `s277_exit75_fixture` | an **autouse fixture** — `@pytest.fixture(autouse=True)` whose body is the same call | `/tmp/s277_p2/conftest.py:16-18` |
| `s277_green_control` | never — `assert 1 == 1` | `/tmp/s277_p2green/test_trivial.py` |

The two phases matter because the phase decides the junit shape: a body-phase abort emits
one childless, **unnamed** `<testcase>` while `testsuite@tests` still reads `"0"`; a
fixture-phase abort emits **no** `<testcase>` at all.

## The pre-fix readings (the RED this PLAN exists to remove)

Measured on this checkout at Step 0, against the **unmodified** classifier:

| stem | child rc | `<testcase>` count | `testsuite@tests` | classifier said |
|---|---|---|---|---|
| `s277_exit75_body` | 75 | 1 (childless, no `name`) | `"0"` | **`GREEN`** — *"the mutation reached disk and nothing reddened — the claim is NOT witnessed, and the guard may be vacuous"* |
| `s277_exit75_fixture` | 75 | 0 | `"0"` | **`NO-TESTS`** — *"the node id selected no tests — nothing ran"* |
| `s277_green_control` | 0 | 1 (childless, named) | `"1"` | `GREEN` — **the identical reason string** |

The body row and the control row differ in the parsed record **only** by
`name='<unnamed>'`. That is the defect: a DB contention is published as *the guard under
test being vacuous*, and a reader acting on it goes to strengthen a guard that is fine.

`MEASURED.json` carries these as `pre_fix_outcome`. 🔴 **That field is a record of the
incident, never a test's expectation** — the AC-6 tests assert `ABORTED` against the
post-fix classifier and must not read it.

## Provenance — what is verbatim and what is not

`MEASURED.json`'s `stdout_provenance` field carries this per stem; it is repeated here
because a reader of the fixtures should not have to open the JSON to learn it.

- **Verbatim** — `s277_exit75_body.junit.xml`, `s277_exit75_body.stdout.txt`,
  `s277_exit75_fixture.junit.xml`. Copied from the preserved capture at
  `~/work/s277_evidence/` (PLAN-0121 SD-4). The md5 of the captured bytes, so the claim is
  checkable rather than asserted:

  | file | md5 | source |
  |---|---|---|
  | `s277_exit75_body.junit.xml` | `e9075bb402f2d6080861725af2cd1d0b` | `s277_p2body/junit.xml` |
  | `s277_exit75_body.stdout.txt` | `675ac2f205e60c44c72955938ad4588e` | `s277_p2body/run.txt` |
  | `s277_exit75_fixture.junit.xml` | `81bad6054c9041cd05ebcf017d17b5d5` | `s277_p2/junit.xml` |
  | `s277_green_control.junit.xml` | `1796e86eb5b172711fdbf7dc5fa9dde7` | `/tmp/s277_p2green/junit.xml` |

  ⚠️ **A whitespace hook will silently break this.** On their first commit,
  `end-of-file-fixer` appended a newline to all three junit captures — i.e. the repo's own
  tooling edited the evidence, which is precisely what a closed-incident pin must not
  tolerate. `.pre-commit-config.yaml` now excludes `^tests/.*/fixtures/` from both
  `trailing-whitespace` and `end-of-file-fixer`. If a future capture lands here with a
  changed md5 and no recorded reason, suspect that exclusion before suspecting the capture.
- ⚠️ **`s277_green_control.junit.xml` — verbatim, but recovered from `/tmp`.** It was
  **not** in `~/work/s277_evidence/`, which preserved `s277_p2ctl` (the `assert 1 == 2`
  RED control) instead. SD-4's note that Step 0 "does not depend on `/tmp` surviving" was
  therefore true of the two abort shapes and **not** of the green control. `/tmp` had
  survived when Step 0 ran (session 279, 2026-09-04) and the bytes were recovered; this
  file is that recovery, and committing it is what finally makes the claim true.
- ⚠️ **`s277_exit75_fixture.stdout.txt` — RECONSTRUCTED, not a raw capture.** No raw
  stdout file was written for the fixture-phase run. The text was recovered from
  `/tmp/s277_p2/OUT.txt`, where the measurement script recorded it as
  `out.strip()[:400]!r` (`classify_feed.py`). It is therefore **stripped** of the leading
  blank line that the body-phase capture shows, and would have been truncated at 400
  characters had it been longer (it is ~110). The two cause-bearing lines are intact and
  are what the fixture is for; the leading whitespace is not.

The body-phase stdout is the shape that matters most, and it is verbatim:

```
(blank line)
no tests ran in 0.18s
! _pytest.outcomes.Exit: TEST-DB-GUARD outcome=CONTENDED holder_pid=424242 db=vero_lite_test_s277 !
```

The cause exists in **exactly one place** — that stdout. It is nowhere in the XML. That is
why PLAN-0121 widens the runner's return to carry a stdout tail.
